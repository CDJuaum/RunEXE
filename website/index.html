Run Windows apps on Linux with less trial and error.

RunEXE is a native Linux frontend for Wine and Proton. It inspects Windows executables before launch, explains likely requirements, chooses a runtime, and keeps each app in its own managed environment.

01 / Workflow

Before you double-click

RunEXE turns an unknown Windows app into a launch plan.

Wine can run a lot of Windows software, but getting from “I have an EXE” to the right prefix, runtime, dependencies, and graphics path is often the hard part. RunEXE puts those decisions in one place and keeps them inspectable.

01

Inspect the file

Read architecture, imports, manifests, version data, .NET requirements, DirectX signals, and AppX/MSIX metadata without launching it.

02

Match the host

Check Wine, Proton, Winetricks, Vulkan, GPU readiness, Qt libraries, and the current Linux distribution before setup begins.

03

Choose a runtime

Prefer Wine for regular desktop apps and Proton for games when that makes sense, while keeping every choice manually overrideable.

04

Launch in isolation

Create or reuse a per-app environment, install known dependencies when requested, and keep launch presets and backups scoped to that app.

Readable diagnostics

Compatibility information you can act on.

RunEXE does not claim to predict whether every Windows program will work. It shows the evidence it can observe locally and tells you what changed the recommendation.

05 / FAQ

Common questions

Before you install.

Does RunEXE replace Wine or Proton?

No. RunEXE is a frontend and management layer. It analyzes the Windows software, discovers or installs compatible runtimes, prepares isolated environments, and launches through Wine or Proton.

Can RunEXE run any Windows EXE on Linux?

No compatibility frontend can guarantee that. Windows APIs, drivers, anti-cheat, DRM, GPU support, and application-specific assumptions still matter. RunEXE aims to make the local compatibility evidence and failure path clearer.

Does analysis run the executable?

No. runexe analyze performs bounded, read-only inspection and can run without Wine. Launching or preparing an environment is a separate action.

What Linux distributions are supported?

Official desktop packages target x86-64 Arch, Debian/Ubuntu-family systems, Fedora/RPM systems, and portable glibc Linux. The CLI also has a musl build for Alpine. RunEXE understands additional package-manager families for host guidance.

Is RunEXE a sandbox?

No. Wine and Proton are compatibility layers, not security sandboxes. Only run software you trust, and use a VM or dedicated sandbox for untrusted executables.
